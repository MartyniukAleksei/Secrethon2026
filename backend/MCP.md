# Secrethon MCP

Наш MCP-сервер надає визначені інструменти читання PostgreSQL та пошуку Tavily.
Він використовує ті ж SQL-запити й правила, що й агент платформи. Ключ Gemini для
MCP не потрібен: модель працює на стороні клієнта. Зміна наявного чату на MCP не
входить у це підключення; зовнішні агенти отримують доступ до інструментів сервера.

## Інструменти

| Назва | Призначення |
|---|---|
| `search_employers` | Пошук за назвою або ІПН, з кандидатами для уточнення |
| `company_profile` | Профіль, санкції, зв’язки, вакансії за місяцем публікації |
| `analytics` | Порівняння, рейтинги, фільтровані підсумки, таблиці та графіки |
| `vacancies` | Вакансії з фільтрами та посиланнями |
| `overview` | Загальні показники й дата зрізу бази |
| `search_mentions` | Кандидати на публічні згадки через Tavily |

Результат має поля `data`, `sources`, `artifacts`, `as_of`, `site_url`.
Графіки повертаються як структуровані специфікації, не як готові зображення.
Відносні посилання джерел потрібно приєднати до `site_url`.
Ресурс `secrethon://methodology` пояснює визначення, джерела та обмеження.
Prompt `research_company` задає послідовність дослідження підприємства.

## Локальне підключення (stdio)

Встановіть залежності (`uv sync` з `backend`). Наш `backend/.env` завантажується
за абсолютним шляхом незалежно від робочої папки клієнта.

Приклад для клієнта з конфігурацією `mcpServers` (замініть шлях, якщо потрібно):

```json
{
  "mcpServers": {
    "secrethon": {
      "command": "C:\\Users\\Admin\\Secrethon2026\\backend\\.venv\\Scripts\\python.exe",
      "args": ["C:\\Users\\Admin\\Secrethon2026\\backend\\mcp_stdio.py"]
    }
  }
}
```

Клієнт запускає локальний процес і спілкується через stdin/stdout. Секрети лишаються
у `backend/.env`. Для цього транспорту окремий `MCP_API_KEY` не потрібен.

## Віддалене підключення (Streamable HTTP)

Endpoint: `https://<домен-платформи>/mcp/` (локально `http://127.0.0.1:8000/mcp/`).
Працює на тому ж FastAPI-сервісі й порту, що й платформа; окремий деплой не потрібен.
Офіційний Python SDK закріплений на підтримуваній гілці 1.x через `mcp>=1.28,<2`.

У Railway Variables сервісу застосунку або локальному `backend/.env` задайте:

```env
MCP_ENABLED=true
MCP_API_KEY=<окремий випадковий ключ доступу>
MCP_PUBLIC_URL=https://<домен-платформи>
```

`MCP_PUBLIC_URL` необов’язковий на Railway, якщо є `RAILWAY_PUBLIC_DOMAIN`.
Для власного домену задайте його явно; для додаткових доменів використайте
`MCP_ALLOWED_HOSTS` (назви через кому, без протоколу й порту).

Клієнт повинен передавати заголовок:

```text
Authorization: Bearer <MCP_API_KEY>
```

Це доступ за спільним ключем, не OAuth. Потрібен клієнт, який підтримує власні
HTTP-заголовки. Без ключа HTTP повертає 503, з неправильним — 401. Після зміни
змінних перезапустіть/перерозгорніть бекенд. Не використовуйте ключі провайдерів
як `MCP_API_KEY` і не вставляйте секрети в URL чи конфігурацію Git.

Якщо сайт захищений HTTP Basic Auth (`SITE_PASSWORD`), для `/mcp/` діє окремий
Bearer-ключ MCP. Логін і пароль сайту для MCP-клієнта не потрібні; решта сайту
залишається під Basic Auth.

Сервер дозволяє 2 одночасні інструменти, обмежує виконання 60 секундами та пошук
Tavily 10 запитами на хвилину на процес. Пошук витрачає кредити Tavily.

## Перевірка

З `backend`:

```powershell
.venv/Scripts/python.exe -m pytest tests/test_agent.py tests/test_mcp.py -q
# Реальна база й Tavily, лише читання; використовує квоту вебпошуку:
.venv/Scripts/python.exe scripts/smoke_mcp.py
.venv/Scripts/python.exe scripts/smoke_mcp.py --transport http
```

Для перегляду схем та ручних викликів можна використати MCP Inspector:
`npx @modelcontextprotocol/inspector`. Виберіть Streamable HTTP, endpoint `/mcp/`
та заголовок Authorization.
